# Your Path Into Tech

## Getting Hired, Networking & Building Skills

Whether you are just starting out or making a career change, this session maps
a realistic path into the tech industry. It explains how hiring works at tech
companies, how to build a resume that makes relevant evidence easy to find, and
how community and networking can open doors. You will also leave with concrete
resources and a 30-day plan for building your skills.

## About the talk

This is a practical 30-minute session for:

- students and self-taught learners pursuing a first tech role
- people changing careers or returning to the workforce
- professionals moving from an adjacent role into more technical work
- anyone who needs a clearer, more sustainable plan than "learn everything"

No single degree, certification, bootcamp, or project guarantees a role. The
talk instead focuses on three things you can improve through repeatable action:

1. **Evidence** - make your skills visible through relevant accomplishments and
   small, complete projects.
2. **Relationships** - participate in communities and build trust before you
   need a referral.
3. **Practice** - learn how hiring works, rehearse the process, and use feedback
   to improve the next attempt.

## What you will learn

| Topic | Practical outcome |
|---|---|
| Choosing a direction | Select one target role family and translate experience you already have |
| Understanding hiring | Recognize what each stage is trying to learn about a candidate |
| Building a resume | Replace task lists with evidence, context, and outcomes |
| Networking with integrity | Make specific, respectful requests and contribute before asking |
| Building skills | Turn learning into small work another person can inspect or discuss |
| Preparing for interviews | Explain decisions, prepare STAR stories, and evaluate the team |

## Your 30-day experiment

Treat this as an experiment, not a test of whether you belong.

| Week | Focus | Concrete actions |
|---|---|---|
| 1 | Choose | Select one role family, review 8-10 current postings, identify recurring requirements, and inventory your evidence and gaps |
| 2 | Learn | Choose one fundamental, schedule three focused sessions, and write a one-page project brief |
| 3 | Ship | Build the smallest complete version, document it, add appropriate proof, and request feedback from two people |
| 4 | Connect and practice | Join one community activity, send two specific messages, rehearse interview stories, and apply to a few well-matched roles |

A sustainable example week might include two 45-minute learning blocks, one
90-minute project block, 30 minutes in community, and 30 minutes for applications
or interview practice. Reduce scope before adding hours.

## Resource toolkit

Do not try to use every resource at once. Pick one roadmap, one learning path,
one practice environment, and one community that fit your target role.

### Explore roles and learning paths

- [roadmap.sh](https://roadmap.sh/) - role-based maps for exploring common skills
  and tools
- [Microsoft Learn](https://learn.microsoft.com/training/) - free, guided
  learning paths for cloud, data, AI, development, security, and more
- [O*NET OnLine](https://www.onetonline.org/) - occupation descriptions, skills,
  tasks, and related roles

### Build fundamentals

- [MDN Web Docs](https://developer.mozilla.org/) - authoritative web platform
  documentation and learning material
- [freeCodeCamp](https://www.freecodecamp.org/) - project-based courses across
  web development, data, and related topics
- [The Odin Project](https://www.theodinproject.com/) - a free, structured
  full-stack web development curriculum
- [freeCodeCamp on YouTube](https://www.youtube.com/@freecodecamp) - free
  full-length video courses; many conferences also publish recorded talks on
  YouTube for free

### Practice and build evidence

- [GitHub Skills](https://skills.github.com/) - hands-on exercises for Git and
  GitHub workflows
- [Exercism](https://exercism.org/) - language practice with feedback and
  mentoring options
- [About READMEs](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes) -
  guidance for making a project understandable and reproducible
- [Managing your profile README](https://docs.github.com/en/account-and-profile/how-tos/profile-customization/managing-your-profile-readme) -
  ways to make relevant work easier to find
- [build-your-own-x](https://github.com/codecrafters-io/build-your-own-x) -
  learn a language deeply by rebuilding familiar tools from scratch

### Contribute to open source

- [Open Source Guides](https://opensource.guide/) - how contributing works,
  from finding a project to your first pull request
- [First Contributions](https://github.com/firstcontributions/first-contributions) -
  a repository built for safely practicing the fork-and-pull-request workflow
- [goodfirstissue.dev](https://goodfirstissue.dev/) and
  [Up For Grabs](https://up-for-grabs.net/) - curated beginner-friendly issues
  across active projects
- [Hacktoberfest](https://hacktoberfest.com/) - an annual October event that
  encourages first-time contributions

Contributions do not have to be code: documentation, tests, issue triage,
translations, and reproducing bug reports are all valuable and all count as
public evidence. Major platforms such as
[Python](https://github.com/python/cpython), [.NET](https://github.com/dotnet),
and [Node.js](https://github.com/nodejs/node) are developed in the open on
GitHub - reading real issues and pull requests is a free education in how
professional software collaboration works.

### Practice coding challenges and games

- [HackerRank](https://www.hackerrank.com/) - skill practice and
  certification-style challenges across languages and domains
- [LeetCode](https://leetcode.com/) - the most common question bank for
  interview-style coding practice
- [CodinGame](https://www.codingame.com/) - learn and practice languages by
  programming bots and solving game-based puzzles
- [Codewars](https://www.codewars.com/) - community-authored "kata" exercises
  with ranked progression in dozens of languages
- [Advent of Code](https://adventofcode.com/) - a playful puzzle series every
  December with a large, supportive community

Use challenge sites as practice reps and interview warm-ups, not as a
scoreboard or a measure of your worth as a candidate.

### Free tools and student programs

- [Python](https://www.python.org/), [.NET](https://dotnet.microsoft.com/), and
  [Node.js](https://nodejs.org/) - professional, open source languages and
  runtimes that cost nothing to install and learn
- [Visual Studio Code](https://code.visualstudio.com/) - a free, extensible
  editor used across many role families
- [Git](https://git-scm.com/) and [GitHub](https://github.com/) - free version
  control and hosting for the projects that become your evidence
- [GitHub Student Developer Pack](https://education.github.com/pack) - free
  developer tools, services, and credits for verified students
- [Azure for Students](https://azure.microsoft.com/free/students/) - free cloud
  credit and services with a student email, no credit card required
- [JetBrains educational licenses](https://www.jetbrains.com/community/education/) -
  free professional IDEs for students and teachers

### Prepare for interviews

- [Tech Interview Handbook](https://www.techinterviewhandbook.org/) - practical
  preparation for technical and behavioral interviews
- [The STAR method](https://capd.mit.edu/resources/the-star-method-for-behavioral-interviews/) -
  a structure for concise, evidence-based behavioral stories

### Find community and free events

- [Global Nerdy meetups roundup](https://www.globalnerdy.com/category/meetups/) -
  Joey deVilla's weekly list of Tampa Bay tech, entrepreneur, and nerd events;
  if you are elsewhere, look for a similar local events roundup or newsletter
- [Meetup technology groups](https://www.meetup.com/find/?keywords=technology) -
  local and virtual meetups and user groups across many specialties
- Community code camps and regional conferences - free or low-cost,
  volunteer-run events (search for "code camp", "DevFest",
  "[SQL Saturday](https://sqlsaturday.com/)", or your local user group);
  volunteering at larger conferences is often a free ticket
- [Major League Hacking](https://mlh.io/) - a season of beginner-friendly
  hackathons, many free and open to students
- [Out in Tech](https://outintech.com/) - community for LGBTQ+ people in tech
- [Blacks In Technology](https://blacksintechnology.net/) - community,
  professional development, and local chapters
- [Techqueria](https://techqueria.org/) - community for Latinx professionals in
  tech
- [AnitaB.org](https://anitab.org/) - programs and communities supporting women
  and nonbinary technologists

Community organizations have different eligibility, local availability, and
participation models. Choose spaces where you can learn, contribute, and return
regularly.

## Presenting or adapting the deck

notes in HTML comments.

```text

|-- themes/custom-default.css # Active presentation theme
`-- img/                       # Local presentation assets
```

Preview `slides/Slides.md` with the
[Marp for VS Code extension](https://marketplace.visualstudio.com/items?itemName=marp-team.marp-vscode),
or export it with Marp CLI v4:

```bash
mkdir -p build

# Interactive HTML, including Mermaid support
npx @marp-team/marp-cli@4 \
  --theme-set slides/themes \
  --html \
  --allow-local-files \
  slides/Slides.md \
  -o build/index.html

# PDF handout
npx @marp-team/marp-cli@4 \
  --theme-set slides/themes \
  --html \
  --allow-local-files \
  --pdf \
  slides/Slides.md \
  -o build/Slides.pdf
```

Pushes to `main` use the included GitHub Actions workflow to publish the HTML
deck and PDF to GitHub Pages after Pages is configured to use GitHub Actions.
